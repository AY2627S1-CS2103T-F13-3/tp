## Overview

PonHub is a JavaFX desktop application for tuition centre administrators who prefer typing commands.
It brings student, tutor and parent records, shared weekly lessons, enrolments and dated attendance
into one application, reducing the need to maintain separate contact lists and spreadsheets.

My main responsibilities were shared lessons, enrolment and attendance, including Lesson editing
and the corresponding commands, tests and documentation. I also maintained domain diagrams,
non-functional requirements and the glossary, and contributed DevOps and packaged application
verification. The examples below describe merged contributions as of **1 November 2026**.

## Features and implementation

### Shared lessons and scheduling

I implemented Lesson IDs, weekdays, times, time slots, subjects and rooms, together with immutable
shared Lesson records. A Lesson stores its own Student roster and can exist before anyone enrols.
The scheduling rules allow adjacent time slots while rejecting overlapping bookings for the same
Tutor or room. See the [scheduling value types](https://github.com/AY2627S1-CS2103T-F13-3/tp/pull/112),
[shared Lesson records](https://github.com/AY2627S1-CS2103T-F13-3/tp/pull/149) and
[scheduling model APIs](https://github.com/AY2627S1-CS2103T-F13-3/tp/pull/161).

I added `addlesson`, resolving an existing Tutor by name and optional exact phone before creating
an independent Lesson with a stable ID. Rejected input, ambiguous Tutors, scheduling conflicts and
failed saves preserve the existing state and allocation counter. Successful creation refreshes
the active lesson queries. See the
[shared recurring Lesson command](https://github.com/AY2627S1-CS2103T-F13-3/tp/pull/185).

### Enrolment and guarded Lesson deletion

I implemented `enrol` and `unenrol`, translating a Student's current displayed position into their
stable ID. Enrolment validates timetable clashes, including a Student attending overlapping lessons
with different Tutors and rooms. Unenrolment changes the current roster while retaining dated
attendance, so an administrator can still inspect and correct a former member's history. People
filters and ordering remain in place, and lesson views refresh after a successful change. See
[membership commands](https://github.com/AY2627S1-CS2103T-F13-3/tp/pull/193).

I also added `deletelesson`, which identifies the roster or attendance dependencies that prevent
deletion. Removing an unreferenced Lesson preserves people records and the allocation counter,
so a deleted Lesson ID is never reused. See
[guarded Lesson deletion](https://github.com/AY2627S1-CS2103T-F13-3/tp/pull/233).

### Dated attendance and retained history

I implemented immutable attendance records keyed by Student ID, Lesson ID and date, with separate
`present` and `absent` outcomes. The `mark` command checks the real date, Lesson weekday and current
enrolment for a new record. Existing records can be corrected after unenrolment, and repeating the
same outcome is a no-op. The `unmark` command removes only the selected attendance key, retaining
other Students, dates and roster entries. Both commands use the existing transaction boundary to
preserve live data, saved bytes and views on failure. See
[attendance records](https://github.com/AY2627S1-CS2103T-F13-3/tp/pull/150),
[attendance marking](https://github.com/AY2627S1-CS2103T-F13-3/tp/pull/211) and
[attendance removal](https://github.com/AY2627S1-CS2103T-F13-3/tp/pull/213).

I later consolidated repeated mark/unmark argument extraction while preserving each command's
allowed prefixes, validation order and feedback. I also centralized weekday/date matching across
restored state, attendance changes and dated retrieval. See
[attendance argument extraction](https://github.com/AY2627S1-CS2103T-F13-3/tp/pull/322) and
[weekday matching](https://github.com/AY2627S1-CS2103T-F13-3/tp/pull/336).

### Lesson editing and everyday usability

I built typed partial Lesson edits and a staged replacement that validates the complete resulting
schedule before publication. The active `editlesson` command preserves the Lesson ID, catalogue
position, roster, attendance and allocation counters. It checks Tutor, room and enrolled-Student
clashes, rejects weekday changes incompatible with retained attendance, and avoids saving identical
edits. See the [staged edit model](https://github.com/AY2627S1-CS2103T-F13-3/tp/pull/325) and
[Lesson editing command](https://github.com/AY2627S1-CS2103T-F13-3/tp/pull/342).

I improved blocked-edit feedback to identify the Student and date of retained attendance, with a
`showlesson` lookup and guidance to refresh the Student position before using `unmark`. I also
supported conventional hyphenated subjects such as `A-Math`, including Unicode length boundaries,
and standardized the positional Student selector used by lesson retrieval. See
[blocked-edit guidance](https://github.com/AY2627S1-CS2103T-F13-3/tp/pull/485),
[subject labels](https://github.com/AY2627S1-CS2103T-F13-3/tp/pull/486) and
[Student-index syntax](https://github.com/AY2627S1-CS2103T-F13-3/tp/pull/487).

Building on Benjamin's retrieval and view features, I improved Lesson cards and attendance-history
cards to distinguish current rosters, former members, recorded statuses and empty results. I added
coverage for long values, narrow layouts, large rosters, cell reuse and overflow. See
[card readability](https://github.com/AY2627S1-CS2103T-F13-3/tp/pull/398).
